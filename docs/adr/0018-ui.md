# 18. The UI is Svelte with @immich/ui

- Status: Accepted
- Date: 2026-10-26

## Context and Problem Statement

Existing ACP clients can chat, but none know about the board, approval queue, grants or parked sessions. Even the per-session approval flows depend on elicitation support, which the RFD lists no implementation of. We need our own UI that works on both desktop and phone.

## Decision Outcome

A Svelte web app using the [`@immich/ui`](https://www.npmjs.com/package/@immich/ui) component library, installable as a PWA.

- **Chat** talks ACP over the runtime's `/acp` WebSocket ([ADR 9](0009-acp.md)): streaming output, tool calls, diffs, permission requests, elicitation and steering.
- **Everything else** uses the runtime API: the session board (grouped by project; active, parked, waiting on me), projects, the approval and proposal queue with renderers, grants and capability requests, standing approvals, and runtime config.
- **Access** is behind the tailnet or ingress with auth.

### Consequences

- Good: a familiar stack and component library, one app for phone and desktop.
- Bad: we own a chat UI, which is a large surface. Existing ACP clients remain usable as fallback chat views.
