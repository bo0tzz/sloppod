# 14. The runtime is written in Rust

- Status: Accepted
- Date: 2026-10-26

## Context and Problem Statement

The runtime does three things: it is a Kubernetes control plane (pods, sandboxes, policies, secrets, TokenRequest, watches), an ACP client and proxy speaking WebSocket, and an API server backed by Postgres.

## Considered Options

- Go: client-go/controller-runtime; ACP via the community [`coder/acp-go-sdk`](https://github.com/coder/acp-go-sdk)
- TypeScript: the official ACP SDK, the same language as the Claude adapter and the UI, weaker Kubernetes tooling
- Rust: the official ACP SDK, kube-rs

## Decision Outcome

Chosen option: **Rust**.

- **ACP:** the official [`rust-sdk`](https://github.com/agentclientprotocol/rust-sdk), including the `agent-client-protocol-conductor` proxy-chain implementation and the `agent-client-protocol-http` transport crate.
- **Kubernetes:** [kube-rs](https://kube.rs), with Rust types for third-party CRDs generated by `kopium` (agent-sandbox, Cilium).
- **Postgres:** sqlx.
- **Authorizer** ([ADR 11](0011-enforcement-at-the-pod-boundary.md)): part of the runtime, serving Envoy's `ext_authz` gRPC API with tonic on its own port.
- **Extension-point contracts** ([ADR 7](0007-extension-points.md)): traits with serde-typed inputs and outputs.

### Consequences

- Good: an official ACP SDK with proxy support, and one static binary.
- Bad: slower to iterate on than Go or TypeScript. Kubernetes operator patterns are less documented than in controller-runtime.

## More Information

In milestone 1 the runtime routes ACP as JSON-RPC messages itself, with the schema crate's shapes in mind, rather than through the SDK's typed handlers. As a proxy it mostly forwards messages, including extension methods like `_session/steering`, with session IDs rewritten. The SDK remains the way to implement a full ACP agent or client.
